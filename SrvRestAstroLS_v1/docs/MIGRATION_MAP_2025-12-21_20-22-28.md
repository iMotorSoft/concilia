# MIGRATION MAP (legacy -> core workspace_id)

Fecha: 2025-12-21

## MIGRATE_REQUIRED (fuera de workspace_id)

- **Legacy DB helpers (tenant/project)**
  - `services/db_concilia_legacy.py:32-184` (ensure_tenant_project, insert_run, update_run, insert_event)
  - Estado: usa `concilia_tenants`, `concilia_projects`, `concilia_runs`, `concilia_events` y env `TENANT_SLUG/PROJECT_NAME`.
  - Impacto: no usa `workspace_id`, no escribe en `core_runs/core_events`.
  - Accion recomendada: reemplazar uso en endpoints con `services/db_pg.py` (core) o wrapper.

- **reconcile_start (telemetria legacy)**
  - `routes/v1/reconcile_start.py:549-559` (ensure_tenant_project + insert_run)
  - `routes/v1/reconcile_start.py:510-535` (insert_event)
  - `routes/v1/reconcile_start.py:655-688` (update_run)
  - Estado: persiste en `concilia_runs/concilia_events` por tenant/project.
  - Impacto: el run_id que llega a SSE es legacy, no core.

- **Claves de aislamiento (no workspace_id)**
  - `routes/v1/reconcile_start.py:537-545` (threadId + uri_extracto/contable)
  - `routes/v1/reconcile_summary.py:162-167` (uri_extracto/contable)
  - `routes/v1/reconcile_details.py:481-770` (uri_extracto/contable)
  - Estado: sin `workspace_id` en API; solo URIs.
  - Impacto: no se puede aplicar row-level isolation directo en DB.

- **UI no envia workspace_id**
  - `clientA/src/components/agui/ReconciliarApp.svelte:241-278` (startReconcile)
  - `clientA/src/components/agui/ReconciliarResumen.svelte:55-126` (summary head/descomposicion)
  - `clientA/src/components/agui/cards/*` (details endpoints)
  - Estado: solo `threadId` + URIs.

## Deteccion de uso legacy en flujo reconcile_start

- `routes/v1/reconcile_start.py:478-698` (reconcile_start)
  - Usa `services/db_concilia_legacy` para run/event
  - Emite SSE `RUN_START`, `RECONCILE_STAGE`, `RESULTS_READY`
  - Propone migracion: wrapper que mantenga SSE y resumen, pero escriba en `core_*`

## Estrategia de migracion (sin implementar)

1) **Wrapper core en reconcile_start**
   - Resolver `workspace_id` por slug (config fijo, ej: `fce-concilia`)
   - Crear run en `core_runs` y escribir eventos en `core_events`
   - Mantener SSE payload actual (no romper UI)

2) **Adapter old->new**
   - Mantener los metadatos legacy solo para compatibilidad (opcional)
   - Hacer `run_id` core el mismo que se reporta a UI (o mapear)

3) **Endpoints de resumen/detalle**
   - Agregar `workspace_id` o `workspace_slug` en query o header
   - Validar que `uri_extracto/contable` pertenecen al workspace

## Old key -> New key (tabla)

| Old key / tabla | New key / tabla | Nota |
| --- | --- | --- |
| `concilia_tenants.id` + `concilia_projects.id` | `core_workspaces.workspace_id` | Old model tenant+project -> new workspace_id |
| `concilia_runs.id` | `core_runs.run_id` | Run id legado -> run id core |
| `concilia_events.id` | `core_events.event_id` | Eventos de stage en core_events |
| `TENANT_SLUG` / `PROJECT_NAME` (env) | `workspace_slug` (env o config) | Nuevo selector de aislamiento |

## Observaciones

- `services/db_pg.py:11-96` ya es core y usa `DB_URL` + `DB_SCHEMA`.
- `services/db_concilia_legacy.py` se mantiene intacto para compatibilidad.
- No hay auth/tenant enforcement en rutas actuales; la migracion debe incorporar `workspace_id` en capa API.
