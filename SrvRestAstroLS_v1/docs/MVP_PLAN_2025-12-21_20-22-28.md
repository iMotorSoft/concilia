# MVP PLAN (3 waves)

Fecha: 2025-12-21

## Oleada A: core runs/events end-to-end (sin tocar reconcile legacy)

Objetivo: escribir en `core_runs/core_events` mientras reconcile_start sigue usando legacy.

Tareas atomicas:
- Resolver `workspace_id` por slug fijo (ej: `fce-concilia`) dentro del flujo reconcile.
  - Ubicacion actual: `routes/v1/reconcile_start.py:478-698` (reconcile_start)
- Crear run core y emitir eventos core (STAGE) en paralelo a legacy.
  - Core helpers: `services/db_pg.py:26-96`
- Mantener SSE payload intacto (RUN_START/RECONCILE_STAGE/RESULTS_READY).
  - SSE: `routes/v1/reconcile_start.py:512-535`

Riesgos:
- Doble escritura (legacy + core) puede causar confusion si no se diferencia en UI.
- run_id core vs legacy: elegir uno para UI o mapear.

## Oleada B: migracion controlada a core (workspace_id everywhere)

Objetivo: reconcile_start usa core helpers; legacy queda solo como fallback.

Tareas atomicas:
- Reemplazar uso de `services/db_concilia_legacy` por `services/db_pg` en reconcile_start.
  - Ubicacion: `routes/v1/reconcile_start.py:510-559`
- Eliminar dependencia de `TENANT_SLUG/PROJECT_NAME` en reconcile_start.
  - Ubicacion actual legacy: `services/db_concilia_legacy.py:32-184`
- Asegurar que `run_id` emitido a SSE es core.
  - Ubicacion: `routes/v1/reconcile_start.py:564-571`

Riesgos:
- UI depende de run_id para reconstruccion futura; si cambia, hay que coordinar.
- Falta de `workspace_id` en input de API (necesario para multi-cliente real).

## Oleada C: UI progreso SSE + reconstruccion

Objetivo: UI puede reconstruir progreso por `run_id` y mostrar estados terminales.

Tareas atomicas:
- Endpoint de reconstruccion por run_id (consulta core_runs/core_events).
  - Contrato: ver `docs/RUNS_EVENTS_CONTRACT_${TS}.md`
- UI consume progreso por `run_id` y muestra timeline de stages.
  - UI base: `clientA/src/components/agui/ReconciliarApp.svelte:121-136`
- Housekeeping de runs colgados -> canceled (job).
  - SQL sugerido en `docs/RUNS_EVENTS_CONTRACT_${TS}.md`

Riesgos:
- UI necesita estado parcial (progress) y puede romper si faltan eventos.
- Reconstruccion requiere payload STAGE consistente.
